# 功能导览

在实际页面上，按步骤介绍已有的具体功能。每一步绑定真实入口或功能区域，极简蒙层圈定正在介绍的位置，说明卡解释它的作用；一般 3–5 步。用户主动开始，也可随时退出。正式设置与业务操作仍由用户完成，结束导览不等于保存设置。

## 结构与外观

| 部分 | 约定 |
|---|---|
| 说明卡 | `Guide` / `.vx-guide-card`；默认底部居中，可用 `placement="left"` 从左侧开始；外缘 24px、内边距 20px，底部／顶部宽不超过 500px，侧边不超过 360px；长内容在卡内滚动 |
| 内容 | 导览名称与步数 → 当前步骤标题 → 一段说明 → 上一步／下一步（末步“完成导览”）；右上角提供退出 |
| 蒙层 | `.vx-guide-mask`，复用 `surface-scrim`，浅深主题自动切换；目标出现后由高亮框外阴影构成挖空蒙层 |
| 目标高亮 | `.vx-guide-hole`；真实目标外留 6px，使用中性细线与蒙层挖空；不加箭头、光晕或装饰标签，不能为了说明卡而截短高亮 |
| 层级 | 通过 portal 挂在 body，使用 `z-modal`；不会被业务容器的 transform、overflow 裁剪 |

用步数表达进度即可，不叠加进度条、装饰箭头或重复退出按钮。说明到动作留 24px，文案保持简短，不把整个操作手册放进说明卡。

优先级是：**真实目标完整可见 → 说明卡避让 → 尽量保持说明卡位置。** 说明卡遵循[容器位置稳定原则](../principles/visual.md#容器位置不随-item-数量跳变)，当前停靠侧仍可用时就保留；长说明内部滚动，不因字数变化重新居中。发生遮挡时才换到有空间的顶部或侧边，目标高亮始终独立跟随真实功能。

## 交互约定

这是**非模态导览**：蒙层降低背景干扰，但不拦截页面点击或锁定焦点。目标输入、选择等操作保持可用；点背景不会意外退出。必须要求用户先答复的操作使用 `Dialog`，不改变导览的语义来模拟模态框。

- 开始时焦点移入说明卡；上下步按钮和卡内左右方向键切换步骤。页面输入保留自己的方向键，Esc 或关闭按钮退出；结束后恢复启动入口。
- `go()` 可先切页或展开区域，完成后定位 `[data-tour]`；主目标不可见则尝试 `alt`，仍缺失则跳过，全部缺失时结束。定位期间显示完整蒙层，仍可退出。
- 已经可见的目标保持页面位置，超出视口时才就近滚入。说明卡与目标之间至少留 12px；不增加半屏页面留白、不裁目标来迁就说明卡。
- 每一步选择具体的功能区域，避免把整页作为目标。目标比视口大时只能框住实际可见部分；整个视口均被目标占满、无法容纳说明时，卡片降为限高滚动显示，目标边界仍保持真实。接入方应把此类目标拆成更具体的步骤。
- 减少动效模式直接定位，其余情况平滑跟随。长列表内导览可用 `scrollRoot` 指定滚动容器。
- 自动触发时机、是否记住完成状态由使用方决定；默认提供“查看导览”入口，避免每次进入都强制播放。

```tsx
const steps = [
  { target: 'search', title: '找到内容', text: '输入标题或关键词。' },
  { target: 'results', title: '浏览结果', text: '打开一项查看详情。' },
]
// 目标元素分别设置 data-tour="search" 和 data-tour="results"
{showGuide && <Guide name="内容浏览导览" steps={steps} onExit={() => setShowGuide(false)} />}
```

完整交互示例见展示页的“选择卡与功能导览”，实际介绍页面上的工作区名称、浏览方式与保存入口。验证底部目标、侧边避让、滚动、窄窗口、浅深主题、输入按键、退出焦点和缺失目标后再接入业务流程。
