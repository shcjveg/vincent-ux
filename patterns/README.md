# 交互模式

交互模式规定多个组件如何配合，让用户理解当前对象、操作影响与完成结果。按正在决定的问题选择模式。涉及自动执行或人机协作时，另需明确执行者与授权边界。

| 设计主题 | 需要决定什么 |
|---|---|
| [页面组合与布局](page-composition.md) | 如何安排阅读顺序、内容密度与响应布局 |
| [导航分组与入口识别](nav-overflow.md) | 如何区分组名和入口，让用户找到目标并辨认当前位置 |
| [内容筛选与选择](browse.md) | 条件何时生效，选择、分页和批量操作各影响哪些对象 |
| [上下文切换与恢复](page-chat-flow.md) | 切换页面与会话时，如何恢复草稿、阅读位置与焦点 |
| [功能导览](guide.md) | 如何解释目标并保持其可操作，用户如何退出 |
| [方案选择与执行授权](decision.md) | 哪些依据须在选择前展示，何时确认、调整或接管 |
| [待处理事项与提醒](todo-and-badge.md) | 如何汇总需要关注的事项，提醒应出现或消失在何处 |
| [处理与历史记录](task-workspace.md) | 在异步工作区中如何衔接待处理状态、实际操作与结果记录 |
| [执行者标识](actor-mark.md) | 自动处理或 AI 参与时，哪些结果需要标明来源 |
| [自动执行的授权范围](write-levels.md) | 哪些操作可以直接执行，哪些结果需先取得授权 |
| [委派时的上下文](delegate.md) | 将工作交给 AI 时，如何带上当前对象、要求与范围 |
