# 基础设计原则

界面的目的：让人用有限的注意力，看懂当前情况，做出判断，并完成行动。设计系统用三个互不替代的维度作决策：**信息取舍、感知表达、行为时序**。颜色、间距、卡片和动效都是实现手段，不是新增原则。

| 原则 | 负责什么 | 判断问题 | 规范落点 |
|---|---|---|---|
| 任务清楚 | 信息取舍：呈现什么、先后顺序、哪些属于同一件事 | 人现在要完成什么？判断所需的对象、状态、后果和下一步是否齐全？其余是否可以延后？ | [内容](content.md)、[交互](interaction.md)的信息递进 |
| 感知省力 | 感知表达：怎样看清、辨别和比较这些信息 | 同一含义是否用同一种表达？层级能否由对齐、留白和明度读出？有没有重复强调或过长的阅读路径？ | [视觉](visual.md)、[页面组合](../patterns/page-composition.md) |
| 行为可预期 | 行为时序：操作前后、状态变化与恢复 | 控件是否说到做到？内容变化是否保留位置与上下文？等待、结果、失败、退出是否明确且可恢复？ | [交互](interaction.md)、组件与对应模式 |

**适用底线**是内容真实、信息完整可辨、操作可达；[无障碍](accessibility.md)将这条底线变成可检查的条件，贯穿三个维度，不另造一套视觉风格。

## 冲突时如何决策

先满足底线，再保证当前任务，再降低认知与操作成本，最后处理装饰和个人偏好。不能用“极简”“统一”“稳定”删掉任务必需的信息或阻止用户完成动作。若某条具体样式规则妨碍前三项，应修改那条规则，而不是要求页面迁就它。

| 实际冲突 | 决策 |
|---|---|
| 导览说明卡固定，但挡住真实目标 | 目标完整可见优先，说明卡换到可用位置；不截掉高亮来维持卡片位置 |
| 想要透气，但窄窗口装不下表格 | 保留可读字号与操作区域；先重排分栏，必须逐列比较的数据局部滚动，页面外壳不被撑开 |
| 想减少色块，但控件或选中项不可辨 | 保留必要的边界、选中与焦点；移除重复对号、重复标签和无意义底色 |
| 想收起次要信息，但隐藏后无法判断 | 影响费用、风险、范围与动作结果的信息留在摘要；只有依据展开过程和历史记录默认收起 |
| 想让页面饱满，但内容很少 | 收窄阅读范围、聚合相关内容；不扩大卡片或复制指标来填空，不给独立对象强加相同高度 |
| 多件独立事项都需要决定 | 每件事项内部一个主动作；通过分组与任务先后控制整页负担，不机械规定整屏只有一个按钮 |

## 验证与回补

先验证组件的状态与操作，再把组件放回真实页面：同时看顶部与长页下半部、展开内容、加载／空／失败、不同数据长度、窄窗口和对话打开时的布局。组件均合规仍不协调，通常缺的是组合约定；先在页面证明解法，再把跨页面复用的部分补入模板或模式。产品独有流程留在产品中。
