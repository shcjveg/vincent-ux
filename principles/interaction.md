# 交互原则

管「怎么用」：注意力、操作层级、状态、反馈、信息密度。视觉外观见 `visual.md`，人与 AI 的分工模式见 `patterns/`。

## 人只在关键节点出现

- 优先突出当前需要确认、判断、指方向的事。自动完成和 AI 完成的过程默认安静，历史过程可收起；失败、风险或影响当前判断的结果必须可见，重要性由任务决定，不由执行者决定。
- 所有需要人介入的环节都是一种待办，在一处统一管理，点击直达处理位置。详见 `patterns/todo-and-badge.md`。

## 一个区域一个主按钮

- 一个独立任务区域内最多一个主按钮（墨色），它是「推荐的下一步」。其余是次按钮（凹面）或文字按钮。
- 区域以独立任务为界（表单、决定卡、弹窗），不用整屏机械计数；示例可用 `data-vx-region` 明确审计边界。
- 按钮放在它作用的对象旁边；相关元素视觉上聚拢，不把操作放到无关的层级上。
- 同一个动作全程同名：按钮叫「批准提交」，结果就叫「已批准提交」。

## 信息递进

- 每页先给结论（一个标题 + 一句话），再给要处理的，最后是参考信息。
- 次要明细默认用收起区（`fold`）；影响当前判断的费用、风险、范围和不可逆后果必须在确认前可见，不能只藏在依据里。

## 每个组件都有完整状态

| 状态 | 表现 |
|---|---|
| 默认 | 中性面 |
| 悬停 | 叠 `fill-hover` |
| 按下 | 位移 0.5px |
| 聚焦（键盘） | 独立焦点环 `focus-ring` |
| 选中 | 控件按自身规则显示选中；白卡式选项只用强调色淡底 + 细框，不叠加对号 |
| 禁用 | 不透明度 0.45，不响应 |
| 加载中 | 首次加载用骨架；刷新保留已有内容；按钮忙碌时原生禁用并保持尺寸 |

## 反馈要说清下一步

- 空状态：说明为什么空、怎么让它不空，给一个动作。
- 出错：说明发生了什么、怎么办；不道歉，不含糊。
- 有实质后果且不可逆的操作先确认，写明对象、范围与后果；可撤销的轻操作直接执行并提供撤销，避免重复确认。
- 轻提示（toast）：只报告刚完成的动作，几秒后自动消失，不打断。

## 红点不制造焦虑

- 只有「现在必须处理」的事产生红点，且只出现在入口上；人已经到了那里，就不再提醒。具体规则见 `patterns/todo-and-badge.md`。

## 动效只为衔接

- 动效只用来说明「从哪来、到哪去」：同一个东西换位置时连续移动过去，不消失再出现；换内容时只淡入新内容，不整块闪。
- 不从固定角落飞入，不回到起点重来。导览高亮框从上一个目标移到下一个目标；跨页时从旧位置移到新位置，页面滚动时跟着目标走。
- 时长按距离走：短距离 120ms，换位 280ms 左右缓出；系统开启「减少动态效果」时直接到位。

## 请求与恢复

提交前校验字段，错误贴近字段并关联说明；提交失败保留输入，给重试。执行期间阻止重复提交；成功后明确完成了什么。浏览刷新保留查询条件和旧结果，失败时标明未更新，不能伪装成空结果。组件呈现状态，业务层负责请求、取消过期请求和成功／失败判定。
